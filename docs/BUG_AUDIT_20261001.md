## Database delivery and remaining decisions

`20261001104307_restore_catalog_task_lifecycle.sql` replaces only `private.enforce_task_rules()`. It does not add permissions, change RLS, delete data, reroute existing requests or run a bulk backfill. It adds automatic archiving to the exact captured live function without changing catalog/priority validation, date rules, account-removal/reference history or resequencing behavior. Historical unknown completion and archive dates remain unknown. It is not applied to production.

Existing completed-but-unarchived rows need a separately reviewed production count/preview and backfill after deployment authorization. See docs/deployment/AUDIT_RELEASE_PLAN.md for boundaries and rollback. They are repaired by future valid edits under the new trigger, but this is not a substitute for a reviewed one-time correction. The production function definition and migration history were inspected read-only on 2026-10-01. The new migration is absent. tests/sql/fixtures/live-task-rules-20261001.sql records the verified baseline and docs/deployment/rollback-task-autoarchive.sql restores that function if needed.

Assistant server prompt changes and the checked-in session-audit lifecycle fix require separately authorized Edge Function deployment. Live session-audit v9 lacks closed-session resumption and calls a removed RPC; the repository implementation avoids that call. Its production origin allowlist is preserved. A GitHub Pages frontend deployment alone will not deploy the database migration or Edge Function.
