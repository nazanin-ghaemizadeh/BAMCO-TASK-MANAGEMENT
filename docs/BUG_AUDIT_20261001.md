## Database delivery and remaining decisions

`20261001104307_restore_catalog_task_lifecycle.sql` replaces only `private.enforce_task_rules()`. It does not add permissions, change RLS, delete data, reroute existing requests or run a bulk backfill. It restores catalogue-based validation and automatic archiving while preserving account-removal/reference history and resequencing behavior. It is not applied to production.

Existing completed-but-unarchived rows need a separately reviewed production count/preview and backfill after deployment authorization. They are repaired by future valid edits under the new trigger, but this is not a substitute for a reviewed one-time correction. The actual production function definition and migration application state have not been inspected.

Assistant server prompt changes require separately authorized Edge Function deployment. A GitHub Pages frontend deployment alone will not deploy the database migration or Edge Function.
