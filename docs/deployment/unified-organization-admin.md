# Central organization administration

The **مدیریت جامع سازمان** route is available to the global system administrator under **مدیریت کاربران**. It manages departments, nested units/teams, people, organizational positions, feature availability, reusable access packages, bulk assignments and effective permissions from one signed-in session.

The existing three data namespaces remain intact. Central unit records link to their native `organization_units`; existing positions are linked to their current unit without changing their reporting lines. Central administration can read and edit all three through guarded RPCs. New units without a parent use the main data workspace; nested teams inherit their parent workspace. This does not provision a separate database for every deputy or merge existing business records.

Position → parent position remains the authoritative reporting line. Roles describe positions. Access packages are independent: observer, creator, editor, approver and unit manager are initial reusable templates. They can be edited or replaced; assigning one to a unit applies it to current and future members. Individual bindings and bulk assignments use the same resolver. Package permissions never include `manage_access` or `bypass_approval`; sensitive organization/account administration cannot be granted by an ordinary package.

For existing units, feature availability initially inherits the current configuration and all legacy direct grants are retained. Saving the feature board makes the active set an explicit ceiling for that unit. A package allows only its checked actions on enabled features. An explicit direct deny wins over a package allow. Removing a package removes only that package's contribution; an independent direct/organizational-role grant can still permit access, and the Effective Access panel displays those direct grants. Global administrators keep their protected access.

Business-object row rules, ownership, reporting-line checks and approval-stage rules remain in force. A package does not confer visibility over another unit's documents/tasks beyond the existing policies of that feature. Changing a user's unit does not copy or reassign their historic records. This panel does not advertise a generic self/unit/all row-scope selector where the feature has no such enforcement.

Central tables live in `private` with RLS enabled and no client table grants. Every admin RPC checks the global manager on the server, including calls through process/quality aliases. The account gateway resolves the target namespace from the server-owned unit, checks the same manager guard, then calls the existing scoped account-management Edge Function. No service key is exposed to the browser. New account credentials are displayed only once in the creation dialog. No real test accounts should be left in production.

Writes are serialized and recorded in a private audit log. Unit, department and package edits use revisions to reject stale saves. Feature metadata invalidations refresh recipient access through the existing realtime/focus recovery mechanisms. Administrative snapshots and dialogs are cleared when the session ends.
